# 银行流水

银行流水只证明资金收付。生成凭证前，先匹配合同、发票、回单或已入账往来，并使用账套中的对应银行明细科目。

- 流水摘要或对方户名不能单独证明主营、费用或往来性质。
- 收付款优先冲销已确认的应收、应付或其他往来，不重复确认收入或费用。
- 同一主体账户间调拨先识别转入和转出账户；不要默认挂内部往来。

## 读取银行流水文件时合并凭证

当本次任务是根据一个银行流水文件批量记账时，先按业务性质归集，再按下面业务类型合并生成凭证，不要按流水行逐笔各做一张凭证：

- 主营业务收款：全部合并为一张凭证，银行存款借方对应应收账款贷方。
- 主营业务付款：全部合并为一张凭证，应付账款借方对应银行存款贷方。
- 银行费用：全部合并为一张凭证，财务费用借方对应银行存款贷方。

合并时保留每笔交易对应的银行明细科目、对方户名和摘要作为证据；工资发放按下节汇总；其他业务按其性质或用户要求处理。

## 发放工资汇总

同一账套、同一月份的工资发放（含属于职工薪酬的提成）合并为一张凭证，跨付款日期或银行流水文件也一并汇总。先参考账套上月的发放口径，通常以月末为凭证日期，按实际付款总额借记应付工资、贷记对应银行存款。

- 工资业务分录也按科目、方向、币种、汇率及必要辅助核算等完整核算属性汇总，不逐人、逐次或单独按提成拆分。银行分录按实际银行明细及完整核算属性分别汇总；同一应付工资科目和同一银行账户通常只需一借一贷两行。不同现金流项目、数量核算等有意义的属性保留区分。
- 凭证摘要和全部分录摘要统一写“发放工资”，不单列“支付提成”，不将员工名单、来源文件或核对过程写进摘要。交易日期、人员及原流水摘要保留在来源或工作证据中。
- 该汇总仅处理实际发放；工资计提、社保公积金及个税缴纳、个人费用报销分别处理。不能仅凭摘要含“工资”就把计提凭证纳入删除或合并范围。
- 用户要求合并已入账凭证时，先核对整批范围和待确认事项，保留原凭证及汇总映射作为恢复证据，再按 MCP 支持的操作替换。完成后确认原付款凭证已删除、汇总凭证唯一且已过账、各科目各方向发生额与合并前一致、计提等其他凭证不变；部分失败时核对当前系统状态后再继续，避免重复付款记录。

## 凭证内汇总银行分录

付款、收款和银行费用凭证包含多笔交易时，除工资发放按上节同时汇总业务分录外，业务分录按各笔交易保留，银行分录在同一张凭证内累计合并。先列业务分录，再列汇总后的银行分录，不再为每笔交易重复列一条银行科目。

- 付款：逐笔列应付账款等业务科目的借方，银行存款贷方列付款合计。
- 收款：逐笔列应收账款等业务科目的贷方，银行存款借方列收款合计。
- 银行费用：逐笔列财务费用等已确认业务科目的借方，银行存款贷方列费用支付合计。
- 仅合并银行明细科目、借贷方向、币种及辅助核算一致的银行分录；不同银行账户分别汇总，借贷发生额分别累计，不以收支净额替代。沿用原凭证的账套、期间和业务分类，不为汇总银行分录扩大合并凭证范围。
- 汇总金额使用原交易金额按账套精度准确求和；有原币金额时同步累计。银行汇总行使用概括摘要，逐笔来源关联、对方户名、原摘要和金额保留在凭证来源或工作证据中。
- 提交前核对：每组银行汇总金额等于对应来源交易合计，业务分录完整、无重复，整张凭证借贷相等。

例如，同一银行账户支付三笔货款 100、200、300 元：借方依次列“应付账款—甲 100”“应付账款—乙 200”“应付账款—丙 300”，最后只列一条贷方“银行存款—该银行明细科目 600”。

## 复用数据处理工具

同一账套、期间的全部银行流水一起交给插件内置 `scripts/process-sources.mjs bank` 读取，复用适配器、分类和核对函数；内部转账保留双边来源，只记一次。 每次任务直接调用现有工具，不另写读取、分类或核对脚本，不在资料目录保存中间文件。调用方式和异常处理见[工具说明](../../scripts/README.md)。

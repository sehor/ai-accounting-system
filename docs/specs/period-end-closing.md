# 期末结账开发计划

## 目标与边界

在现有“会计期间 → 关账”流程中增加可人工触发的期末结账步骤。系统只在用户点击对应卡片后生成并立即记账，不自动生成以下凭证：

1. 计提固定资产折旧；
2. 结转本期损益中的成本、费用；
3. 结转本期损益中的收入；
4. 12 月（年末）结转本年利润。

本次不增加“转出未交增值税”、附加税或所得税计提卡片，也不自动创建缺失的结账科目。

## 会计规则

### 1. 折旧

- 复用现有固定资产月度折旧计算、受益对象和辅助核算逻辑。
- 借：制造费用、管理费用等受益对象对应的费用/成本科目；贷：累计折旧。
- 折旧金额按固定资产实际应计提金额计算，分部门等辅助核算维度生成明细。
- 已生成的折旧凭证重复点击时保持幂等；固定资产输入变化时标记为 `STALE`，再次生成时更新原生成凭证。

### 2. 费用结转

- 只处理 `EXPENSE` 类叶子科目，包括主营业务成本、销售费用、管理费用、财务费用等。
- `COST`（例如生产成本）不直接结转本年利润，保留在成本类科目中。
- 按科目本期实际净余额判断方向：
  - 费用借方净额：借本年利润，贷费用科目；
  - 费用出现贷方净额：借费用科目，贷本年利润。
- 多个费用科目合并生成一张结转凭证，金额为各科目实际净额。

### 3. 收入结转

- 处理全部 `REVENUE` 类叶子科目。
- 按科目本期实际净余额判断方向：
  - 收入贷方净额：借收入科目，贷本年利润；
  - 收入出现借方净额：借本年利润，贷收入科目。
- 多个收入科目合并生成一张结转凭证。

### 4. 年末结转本年利润

- 仅在期间代码为 `YYYY-12` 时显示并允许生成。
- 结转“本年利润”到“利润分配—未分配利润”。
- 盈利：借本年利润，贷利润分配—未分配利润；亏损：借利润分配—未分配利润，贷本年利润。
- 结转后本年利润余额必须为零；非年末期间不显示该卡片，也不接受该步骤 API 请求。

### 5. 科目配置

- 保存账套级配置：本年利润科目、利润分配—未分配利润科目。
- 默认按会计准则匹配：SME `3103/3104`，CAS `4103/4104`。
- 当前科目表缺失时只显示配置缺失阻塞原因，由用户通过齿轮选择已有叶子科目；不得自动创建科目。
- 配置的科目必须属于当前账套、状态有效且为叶子科目，且类别符合结转用途。

## 后端实施计划

### 1. 数据库迁移

新增 Flyway migration（下一版本号）：

#### `period_closing_setting`

- `ledger_id` 主键并关联账套；
- `profit_account_id`、`retained_earnings_account_id` 可为空，使用账套级复合外键关联科目；
- 创建/更新时间及版本字段；
- 不在迁移中创建缺失科目。

#### `period_closing_step`

- `ledger_id`、`period_id`、`step_type` 唯一；
- `status`：`NOT_REQUIRED`、`PENDING`、`GENERATED`、`STALE`、`BLOCKED`；
- `amount`、`input_fingerprint`、`voucher_id`、创建/更新时间；
- 关联期间和凭证，保证同一期间同一步骤最多一条业务记录。

指纹覆盖参与计算的期间余额、相关科目、固定资产折旧输入和科目配置。凭证生成后重新计算指纹，输入变化即标记 `STALE`。

### 2. 领域接口与控制器

新增 `periodclosing` 模块及服务：

- `GET /v1/ledgers/{ledgerId}/period-closings/{periodId}`：纯读返回步骤状态、金额、凭证 ID、阻塞原因、试算平衡结果和 `canClose`，不得执行 `INSERT`、`UPDATE` 或其他数据库写入；缺失步骤在响应中计算为 `PENDING`，`STALE`、`BLOCKED` 等临时状态也只在读取时计算；
- `POST /v1/ledgers/{ledgerId}/period-closings/{periodId}/steps/{step}:generate`：按用户点击生成指定步骤，`step` 取值：
  - `DEPRECIATION`
  - `EXPENSE_TRANSFER`
  - `REVENUE_TRANSFER`
  - `YEAR_END_PROFIT_TRANSFER`
- `GET /v1/ledgers/{ledgerId}/period-closing-settings`：读取科目配置及默认匹配结果；
- `PATCH /v1/ledgers/{ledgerId}/period-closing-settings`：保存科目配置。

生成接口要求：

- 校验账套角色、期间状态、期间顺序和科目配置；
- 生成后立即记账，沿用 `VoucherService.createGenerated/replaceGenerated`；生成凭证归 `periodclosing` 来源模块所有，通用凭证修改、恢复和删除入口不得处理；
- 重复点击幂等；
- 输入指纹不一致时更新原生成凭证，而不是新建重复凭证；
- 辅助核算必填但无法提供明细时返回结构化阻塞错误；
- 年末步骤在非 12 月请求时返回 `YEAR_END_STEP_NOT_ALLOWED`。

### 3. 结账硬门槛

保留现有 `POST /v1/ledgers/{ledgerId}/periods/{periodId}:close`，但在真正更新期间状态前重新执行全部检查：

1. 余额投影已就绪且与最新业务事实一致；
2. 重新读取最新投影后，叶子科目三组试算合计分别满足：
   - 期初借方合计 = 期初贷方合计；
   - 本期发生借方合计 = 本期发生贷方合计；
   - 期末借方合计 = 期末贷方合计；
3. 前一期间已经结账；
4. 本期间为最后一个已结账期间时才允许反结账，反结账按期间倒序执行。

任一差额不为零、投影未就绪或顺序不满足时：

- 前端显示具体差额和阻塞原因并禁用“结账”；
- 后端返回结构化错误码、标题、详细阻塞原因和三组差额；
- 不更新期间状态。

建议错误码：`PERIOD_CLOSING_INCOMPLETE`、`PERIOD_CLOSING_STALE`、`PERIOD_CLOSING_ACCOUNT_CONFIG_MISSING`、`PERIOD_CLOSING_AUXILIARY_DETAIL_MISSING`、`TRIAL_BALANCE_UNBALANCED`、`BALANCE_PROJECTION_NOT_READY`、`PERIOD_ORDER_INVALID`。

## 前端实施计划

在现有 `SettingsPage` 的会计期间关账弹窗中增加 `PeriodClosingPanel`：

- 普通月份显示三张卡：计提折旧、结转费用、结转收入；
- 12 月追加“结转本年利润”；
- 卡片显示金额、步骤状态、阻塞原因、生成/重新生成按钮；
- 已生成凭证提供凭证查看入口；
- 齿轮弹窗配置本年利润和利润分配科目；
- 底部显示期初、本期发生、期末三组借贷合计及差额；
- 仅当三组试算平衡、余额投影就绪且前一期间已结账时启用“结账”；计提折旧、结转费用/收入步骤均为可选的辅助生成，不阻塞结账；
- 生成、重新生成和科目配置成功后刷新结账状态、期间列表和凭证缓存；
- 不展示增值税转出、附加税或所得税卡片。

前端新增 API 类型：步骤、结账状态、试算合计、阻塞原因和科目设置；沿用现有 `apiFetch` 与 React Query 缓存策略。

## 测试计划

### 后端

- 会计规则：正常利润、亏损、反常借贷方向、多费用/多收入科目；
- 分类：`EXPENSE` 结转、`COST` 保留、`REVENUE` 结转；
- 年末：12 月显示并结转本年利润，非年末不显示且接口拒绝；
- 幂等：重复生成不新增凭证，业务变化后变为 `STALE` 并更新原凭证；
- 配置：缺少默认科目、无效科目、非叶子科目、辅助核算缺失；
- 试算：期初、本期发生、期末任一组不平衡时关闭接口拒绝；
- 投影未就绪、试算不平衡或期间顺序不满足时拒绝结账；
- 跨期结账必须按顺序，反结账必须按倒序；
- 控制器测试覆盖状态、生成、设置读取/更新和结构化错误响应；
- 与现有固定资产折旧集成，验证折旧凭证来源和金额。

### 前端

- `SettingsPage` 普通月份/12 月卡片显示；
- 生成、重新生成、凭证入口和状态刷新；
- 科目齿轮配置；
- 三组试算合计和差额显示；
- 试算不平衡、投影未就绪或期间顺序不满足时“结账”按钮禁用；计提折旧和结转步骤未完成不再禁用结账；
- 后端返回阻塞原因时展示具体中文提示。

## 实施顺序

1. 先补充领域接口、响应模型和数据库迁移；
2. 实现结账设置及步骤仓储；
3. 实现四类凭证生成、指纹和幂等更新；
4. 接入试算平衡和期间顺序硬门槛；
5. 更新关账弹窗和科目配置交互；
6. 编写并运行定向后端、控制器和前端测试；
7. 执行 `graphify update .`，检查图谱更新；
8. 复核迁移、API 文档、错误码和测试结果后再提交实现代码。

## 验收标准

- 用户可以逐张点击生成凭证，系统不自动生成结账凭证，也不强制先完成结转步骤才能结账；
- 四类凭证方向、科目范围和金额符合上述会计规则；
- 生成后立即为 `POSTED`，重复点击幂等，输入变化可识别并更新；
- 试算三组全部平衡、余额投影就绪且前一期间已结账才可结账，后端始终是最终硬门槛；
- 期间结账和反结账顺序受强制约束；
- 全部相关定向测试通过，且不引入增值税转出或税费计提功能。

# 下一版改进方向

本文记录本轮评审中明确暂缓、不改变初版行为的事项，避免问题从计划中消失。

## 已明确暂缓的业务与安全事项

1. **凭证保存即自动审批并记账**
   - 初版继续保留当前简化流程。
   - 下一版应把创建、校验、提交、审批和记账拆成显式状态转换，并明确制单人与审批人的权限边界。
   - 验收标准：审批开启时，未经授权的人类审批不得进入 `POSTED`。

2. **MCP 工具白名单过宽**
   - 初版继续保留现有 MCP 工具集合。
   - 下一版应区分 Agent 可调用工具与仅供人工 REST 操作的命令，并用自动化测试锁定工具白名单。
   - 验收标准：MCP 不暴露审批、关账、重新开账和成员管理等人工控制操作。

3. **已记账凭证原地修改，缺少反记账和冲销**
   - 初版继续允许当前简化修改方式。
   - 下一版应实现显式反记账、重新记账和冲销凭证，已记账事实不再原地覆盖。
   - 验收标准：账簿能完整重放每次反记账、修改、重新记账和冲销的影响。

4. **关键业务审计覆盖不完整**
   - 初版不扩展审计范围。
   - 下一版应统一账套、成员、期初余额、凭证和期间操作的追加式审计合同，并在业务事务内写入。
   - 验收标准：所有关键命令均记录操作者、账套、原因、变更前后内容和 traceId。

5. **本地开发配置包含默认数据库密码和开发 token**
   - 初版继续用于本地测试开发，不作为生产配置。
   - 下一版进入部署准备时删除默认凭证，改为缺失即启动失败，并轮换已使用的凭证。
   - 验收标准：仓库配置不含可直接使用的密码或 token，部署凭证仅由环境或密钥服务提供。

## 可维护性持续改进

- 将 `FinanceMcpTools` 按查询、账套、凭证、文档和导入导出拆成多个输入适配器。
- 将 `DefaultLedgerService`、`DefaultVoucherService` 和 `DefaultFixedAssetService` 中的编排与纯业务规则继续分离。
- 完成 ADR-001 中剩余的服务接口和仓储端口迁移，禁止公开服务直接依赖具体 JDBC 仓储。
- 注入统一配置的 `ObjectMapper`，避免各模块自行创建导致序列化规则漂移。
- 集中角色策略，减少各服务重复维护 `Set<LedgerRole>`。
- 为折旧、期初余额、凭证状态和报表建立连续多期间金样测试，不只验证单次 happy path。

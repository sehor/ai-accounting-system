# ADR-004：采用规范维度组合和独立辅助余额投影

## 状态

Accepted

## 日期

2026-08-14

## 背景

现有系统已保存 `voucher_line_dimension` 并校验科目辅助要求，但存在三个断点：

1. `opening_balance.dimension_key` 是客户端自由文本，没有结构化成员或服务端规范化；
2. `JdbcReportingRepository` 不读取凭证维度，旧明细响应始终返回空维度键；
3. `account_period_balance` 仅按账套、期间和科目投影，Finance Query 明确拒绝 DIMENSION 分组。

ADR-002 和 ADR-003 将辅助核算余额排除在首期投影之外。产品规格现在要求完整维度核算，因此需要新增兼容架构，同时不能改变现有法定报表和按科目余额消费者。

## 决策

### 规范组合

引入账套内不可变的 `dimension_combination` 和成员表。组合由排序后的类型和值 UUID 生成规范串，服务端以规范串 UTF-8 字节的 MD5 小写十六进制值生成稳定 `dimensionKey`。事实与投影使用 `combination_id`，规范串承担账套内唯一性；MD5 只作为兼容诊断指纹，不承担加密、授权或唯一性。

类型和值编码、名称写入组合成员快照。停用或改名只影响新组合，历史报表继续显示当时标签。

凭证行和期初余额都引用组合。现有 `voucher_line_dimension` 和期初 `dimensionKey` 字段在兼容期保留。

### 独立投影

保留 `account_period_balance`，新增叶子科目的 `dimension_period_balance`，按期间、科目、维度组合和币种保存原币及本位币滚动余额。
重建必须从前期辅助期末余额与后续权威事实的键并集开始，把无本期发生的键继续滚动；原币和本位币独立累计，借贷金额保留
事实的带符号方向，经营发生额仅包含 `accounting_role='OPERATING'` 的凭证。

现有投影事件只作为脏标记。`BalanceSnapshotRebuilder` 已从权威事实重建余额，因此在同一事务中增加辅助投影重建；两张投影成功后才推进共享 watermark。无需把维度塞入旧事件行，也不改变旧投影接口。

### 查询

Finance Query 以向后兼容字段增加维度过滤和分组，既有 `amount` 始终以本位币计量；币种过滤只限制事实来源，禁止跨币种汇总原币。
既有账簿默认接口不变，复杂维度账簿使用独立查询 endpoint。投影不是 READY 时，辅助余额查询明确失败，不能混用新事实和旧快照。

### 迁移

既有凭证从 `voucher_line_dimension` 确定性回填。空期初键映射空组合；非空旧自由键保存为 `LEGACY_UNMAPPED`，不得猜测。投影从权威事实重建，不把快照作为备份权威数据。

## 备选方案

### 直接事实查询

优点：表少、即时、适合短期间明细。  
缺点：多期间余额和组合分组昂贵；难以与现有投影水位、关账对账和重建作业保持一致。  
结论：仅用于可追溯明细，不作为完整辅助余额来源。

### 扩展现有 account_period_balance 主键

优点：只有一张投影表。  
缺点：改变所有现有报表的行粒度、主键和父科目汇总，破坏兼容并显著扩大迁移风险。  
结论：拒绝。

### 只按单个维度值投影

优点：单维度过滤简单。  
缺点：无法表达客户+项目等多维组合，重复累计时容易产生错误总额。  
结论：拒绝。

## 后果

- 法定报表和原科目余额合同保持稳定；
- 辅助核算具有独立、可重建、可对账的余额来源；
- 新增组合注册、结构化期初、辅助投影和查询代码；
- 写入路径需在一个事务内维护组合 pointer 与现有维度行；
- 滚动发布期间保留旧期初 `ON CONFLICT` 的完整唯一键，并由数据库写入桥把旧空 key/legacy key 解析为组合；
- 备份恢复发生 UUID 重映射后，STRUCTURED canonical key 必须由恢复后的成员重新生成，旧版本回填优先保留已有 pointer；
- 备份格式需升版并包含组合和结构化期初事实，同时保留既有 V1/V2 恢复分支；
- legacy 自由键可能需要后续人工映射工作流，但金额不会丢失或被错误归类；
- 本 ADR 仅在“是否投影辅助核算”这一决策上 supersede ADR-002/ADR-003；其他余额投影和滚动快照决策继续有效。

## 安全与完整性

- 所有组合、成员和事实外键包含 `ledger_id`；
- 组合创建使用唯一约束和 `INSERT ... ON CONFLICT`，避免并发重复；
- 动态查询只允许白名单维度，用户值参数化；
- `dimensionKey` 不是安全边界；
- 关账前验证辅助投影与科目投影的叶子科目汇总一致。
